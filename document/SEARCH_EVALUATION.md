# 检索与筛选评估协议

[项目首页](../README.md) · [架构说明](ARCHITECTURE.md)

本协议用于区分检索、筛选和保存阶段的问题。成功运行、候选增多或单元测试通过，都不能单独证明结果更准确或更全面。公开文档不包含个人任务 ID、模型请求、真实运行日志或维护者的研究结果；联网评估由使用者在自己的数据目录执行。

## 先固定研究范围

评估前写清研究问题、备选分支、纳入与排除条件、年份范围和日期语义。主题中的“或”关系不应转换为全部条件同时满足；论文主题相关度、研究质量与发表状态也应分别记录。

从机制描述而不只是模型名称构建查询，覆盖缩写、全称、同义词与历史术语。不要为了命中已知结果而将基准论文的标题、ID 或特有名称直接加入待测查询。

同一轮比较应固定模型后端、年份、检索来源、最大轮数和每查询预算。扩大年份范围带来的增量与算法改进分开报告。快速模式是一种有限预算运行，不与完整模式直接比较总体召回数字。

## 已知论文基准

[`tests/fixtures/retrieval_benchmark.json`](../tests/fixtures/retrieval_benchmark.json) 是一个公开元数据组成的主题性小样本，包含论文身份、预期决定与理由，用于检查已知漏检和误筛。它不是全领域文献全集，也不是对所有研究领域的代表性抽样。

维护 fixture 时应核对论文的官方身份、首次发表日期、版本关系及撤稿状态，并把判定依据与测试数据一同审查。新增主题时，先独立建立基准，再运行检索，避免用检索自身找到的论文证明检索召回率。

对年份不符合范围的论文，不计入该次召回分母。以首次提交日期为边界时，后续修订年份不能替代首次发表年份。撤稿与主题不相关是不同理由，不应混为一类。

## 分开检验三个阶段

| 阶段 | 问题 | 所需证据 |
| --- | --- | --- |
| 检索 | 已知相关论文是否进入可观察的候选集合？ | 实际查询、来源状态、返回候选、截断与时间预算 |
| 筛选 | 已检索到的相关论文是否被保留，负例是否误入？ | 逐篇原始摘要、模型决定、可核对理由与待复核状态 |
| 保存与展示 | 流程判定是否与最终任务列表一致？ | 四组筛选结果、最终列表、页面/API 返回值 |

筛选独立实验可直接读取基准论文的原始摘要，但不能把这个实验称作检索召回测试。缺失摘要、引用原句校验失败或模型输出无法解析，应进入待复核并报告，不能默认为无关或相关。

来源失败、超时和限流是检索缺口，不是零命中。去重也应保留来源和命中查询，避免合并后丢失证据或撤稿标记。

## 指标与解释

设符合范围的基准正例为 `G`，观察到的去重候选为 `C`，主列表为 `R`，补充阅读为 `S`：

| 指标 | 定义 | 不代表什么 |
| --- | --- | --- |
| 已知论文候选召回 | `|G ∩ C| / |G|` | 全领域召回率 |
| 已知论文主列表召回 | `|G ∩ R| / |G|` | 最终结果准确率 |
| 含补充阅读的保留召回 | `|G ∩ (R ∪ S)| / |G|` | 全部论文都直接相关 |
| 已命中正例的主列表保留率 | `|G ∩ R| / |G ∩ C|` | 检索来源覆盖完整 |

分母为零时报告不可计算。待复核不计为已确认保留，补充阅读不计为主列表命中。逐一列出“未检索到”“检索到但排除”“仅补充阅读”“待复核”，不要用一个总体数字掩盖不同原因。

结果准确率需要从实际结果集独立抽样审查。样本应覆盖各研究分支、来源与评分层级，并报告抽样方式、样本量和相关性判定。固定负例通过率只能说明这些已知边界被覆盖，不能替代准确率估计。

`scripts/evaluate_search.py` 使用任务保存的筛选四组作为可观察候选集合；缺少筛选审计的历史任务，其候选召回无法可靠恢复，应保留未知状态。这与读取所有原始 HTTP 响应得到的候选全集不是同一种观测方式。

## 运行方式

先配置模型后端。以下命令会联网查询学术服务并调用所选模型，使用相应服务的额度；不是默认离线测试的一部分。

```bash
python scripts/run_search_evaluation.py \
  --topic "robot manipulation with tactile feedback" \
  --year-from 2021 \
  --rounds 3 \
  --output outputs/retrieval-evaluation
```

示例展示调用方式。它不保证与仓库中的主题性 fixture 相匹配；计算基准召回前，必须确认研究问题与 fixture 的纳入范围相同，或准备适配该主题的独立基准。

对已经保存在运行中工作台的任务，可使用任务 ID 读取并计算既有 fixture 指标：

```bash
python scripts/evaluate_search.py TASK_ID --output outputs/retrieval-metrics.json
```

此命令读取 `127.0.0.1:8000` 上的任务，不重新搜索或修改任务。`TASK_ID` 需要替换为自己的任务 ID。输出属于本地研究数据，不应随源码提交。

如需修改或组合离线评估产物，先阅读相应脚本的 `--help`，显式指定输入和输出路径，保留原始运行结果，避免用编辑后的结果冒充未干预运行。

## 每次评估应保留的证据

- 软件版本或源代码指纹、模型后端与型号、推理设置、运行时间和预算。
- 原始问题、计划、纳入标准、各轮实际查询与年份语义。
- 每来源的状态、候选数、总命中数（若可得）、截断及限流信息。
- 原始候选、去重映射、可用摘要和最终筛选四组。
- 每篇决定的理由、支持原文、已知论文命中结果与未解决问题。
- 真实运行、离线重算、人工修订及局部重试之间的区分。

这些记录用于本地复核。公开研究结果时，应另行审查数据分发权限和隐私，只提供有授权、脱敏并足以复核结论的材料，不直接打包整个 `outputs/` 或任务目录。

## 建议报告格式

| 项目 | 需要填写 |
| --- | --- |
| 问题与范围 | 主题、年份、概念分支和排除标准 |
| 运行条件 | 代码版本、模型、来源、预算、快速/完整模式 |
| 来源可用性 | 成功、失败、限流、截断及未查询部分 |
| 召回指标 | 基准规模、候选、主列表、含补充阅读的结果 |
| 筛选审查 | 抽样方式、样本量、误纳入和误排除案例 |
| 范围覆盖 | 各分支的实际论文及证据不足处 |
| 局限 | fixture 偏差、观测缺失、预算和服务限制 |

结论应落在可观测证据上。例如，“本次预算内找回若干已知相关论文”是可复核陈述；“已覆盖所有最新研究”则需要该流程尚未提供的证据。
