# 使用手册

[项目首页](../README.md) · [架构说明](ARCHITECTURE.md) · [检索评估](SEARCH_EVALUATION.md) · [综述评估](SURVEY_EVALUATION.md)

本文说明从研究问题到 Markdown 文稿的操作方式。安装与启动见项目首页；接口的实时定义以运行中的 `/docs` 为准。

## 选择检索模式

| 模式 | 输入 | 适合的工作 |
| --- | --- | --- |
| 关键词检索 | 一行一个检索词或短语 | 已有明确术语，进行定向查找 |
| 深度检索 | 一段自然语言研究问题 | 需要拆解概念、覆盖备选路线并逐轮补检 |

关键词可以扩展为同义表达，再选择用于检索的词。深度检索会生成主题计划，区分研究领域、模型家族、目标能力、备选分支与排除项。检查计划时，应特别关注缩写的解释和“或”关系是否仍然是备选，而不是意外变成同时满足的硬条件。

例如，可以输入“机器人操作中，视觉与触觉如何帮助识别接触状态”，并检查查询是否同时覆盖触觉、接触估计及不同机制表达。示例只是输入形式，不是预置的完整基准。

深度检索默认最多 3 轮，可设置为 1–5 轮。快速模式减少候选预算与调用量，适合验证环境和查询表达；其结果不适合用于声称充分覆盖某个领域。

## 阅读检索与筛选结果

默认检索源为 arXiv 和 OpenAlex。每条查询独立分配结果预算，再合并重复论文。日期限制在检索请求中应用；去重时保留来源、命中查询与引用补检线索。系统还会根据结果执行受预算约束的查询放宽、当年论文补检或向后引用补检。

来源诊断区分正常返回、零结果、截断、限流与请求失败。某个来源无法访问时，其余来源的结果仍可保留；失败不能解读成“该来源没有论文”。Google Scholar 不是默认检索源。

| 分组 | 含义 | 如何使用 |
| --- | --- | --- |
| 主列表 | 相关度 4–5 分，直接对应问题或重要子方向 | 默认用于研究总结和详细综述 |
| 补充阅读 | 相关度 3 分，有可迁移机制或背景价值 | 作为扩展阅读，不等同于直接证据 |
| 待复核 | 摘要证据不足、模型输出不合规或无法核对 | 人工检查原文后决定，不默认算作纳入 |
| 排除 | 不符合范围、无足够关联或有明确撤稿状态 | 查看原因，辨别查询噪声与误筛 |

相关度不是论文质量评分，也不是同行评审状态。查看单篇论文时，结合匹配范围、筛选理由与原文证据判断。若检索得到零篇，后续不需要有文献输入的筛选和总结步骤会跳过；应先检查查询与来源状态。

检索记录中保留主题计划、每轮查询与来源状态、筛选四组结果以及覆盖提示。达到轮数或结果上限表示预算用完，不代表领域已经没有遗漏。

## 生成文献综述

在任务详情中打开“文献综述”。默认使用主列表全部论文；如果已在论文列表勾选条目，可以沿用并调整选择。建议在写作要求中说明研究问题、比较维度和边界，例如区分模型预测与真实闭环执行，或区分方法机制与实验效果。

### 详细综述

详细综述使用 `survey` 模式，支持中文和英文。流程包括：

1. **固定输入**：保存任务、论文、筛选资料与写作配置的快照，固定全局引用编号。
2. **准备证据**：优先读取 arXiv HTML 全文；不可用时复用已有 PDF，最后回退到原始摘要并标明级别。
3. **组织提纲**：为全部所选论文分配主题章节，而非固定抽取少数代表作。
4. **分章写作**：综合方法、机制、实验条件与局限，生成正文、比较表和原文引证。
5. **检查与审校**：校验正文引用、同篇同段原文摘录和覆盖，随后进行模型语义审校。
6. **综合与导出**：生成导论及讨论，审校终稿并保存 Markdown、参考文献和覆盖附录。

不需要先手动下载 PDF 或生成 Reference Cards。arXiv `/abs/` 是摘要页，不能替代 `/html/` 全文；没有 HTML 不意味着没有论文。仅有标题和元数据的条目不能提供可核对原文，流程会说明缺少资料。

全文来源标记说明已获取全文，不代表每个段落都进入模型上下文。分章写作按问题选择片段；“当前片段未覆盖”不能写成“论文没有该能力”。

### 停止、继续与版本

刷新或离开页面不会停止后台作业。可以“停止并保留进度”，之后对可恢复版本选择“继续生成”。恢复使用原始输入快照，复用通过校验的章节；服务重启后，未结束的任务不会自行重新消耗模型额度，需要手动继续。

修改论文范围、模型或写作要求时应创建新版本。输入快照缺失、损坏或不再匹配时，界面会显示原因；不要直接修改检查点绕过校验。生成中的综述和所属任务不能删除。

完整文稿自动保存为：

```text
task_data/<主题>__<task_id>/reviews/<review_id>/review.md
```

页面支持版本切换、目录定位和 Markdown 导出。任务标签保存在 URL 中，例如 `/task/<task_id>?tab=review`。尚未完成的版本可能有可导出的部分正文；导出成功不代表该版本已通过终稿审校，应同时检查版本状态。

### Related Work、卡片与模板

`related_work` 用于论文中的短篇相关工作段落。它使用卡片规划与短节写作，不承诺覆盖全部选定论文，也不提供详细综述的逐章恢复。

Reference Cards 是模型提取的结构化编目辅助，不是人工核验结论。详细综述的事实依据仍是可追溯原文片段。指令预设用于复用写作要求；期刊或范文模板只提供行文风格，不应作为本次研究事实的来源。使用模板时，其内容会进入模型请求。

## 模型配置

在项目根目录的 `.env` 配置一种模型后端。修改配置后重启后端。不要在前端环境变量中放密钥：浏览器代码中的变量不能作为秘密保存。

### Codex CLI

CLI 安装方式见 [OpenAI 官方说明](https://learn.chatgpt.com/docs/codex/cli)。运行后端的用户需要能够执行 `codex`，并已有可用登录。先用 `codex login status` 检查；必要时在自己的终端运行 `codex login`。命令不在 PATH 时，设置 `CODEX_CLI_PATH` 为其可执行文件路径。

本项目适配器为每次请求建立独立临时会话，使用只读工作目录，禁用网页搜索、shell、hooks、插件和应用工具，仅基于项目传入的文本生成回答。它忽略个人 `config.toml` 的模型与扩展设置，不修改个人配置。凭据由 CLI 根据现有用户环境自行读取与刷新，项目不要求导入认证文件。

`CODEX_MODEL` 留空时使用 CLI 内置默认值，不继承个人配置中的模型，也不使用 `OPENAI_MODEL`。需要指定模型时，请选择自己的账户可用型号；推理强度也必须受该模型支持。适配器依赖 CLI 的 `exec`、独立会话及配置隔离选项，旧版本若报未知参数，需要使用支持这些选项的 CLI 版本。

CLI 模式在完成后一次返回正文，不提供逐 token 流式显示。界面的阶段与章节进度仍可正常更新。当前适配器只接受文本，不支持图像输入、模型工具调用或完整 LangChain Runnable 协议。

### OpenAI 兼容 API

设置 `LLM_PROVIDER=openai`，并填写 `OPENAI_API_KEY`、`OPENAI_BASE_URL` 和 `OPENAI_MODEL`。模型名称、接口能力和参数支持由服务商决定，不能仅凭兼容地址假定所有功能可用。不要将真实密钥写入示例、Issue 或测试 fixture。

| 变量 | 默认 / 示例 | 作用 |
| --- | --- | --- |
| `LLM_PROVIDER` | 未设置时 `openai`；示例选择 `codex` | 模型后端 |
| `CODEX_CLI_PATH` | `codex` | CLI 命令或路径 |
| `CODEX_MODEL` | 空 | 可选的 CLI 模型覆盖 |
| `CODEX_REASONING_EFFORT` | 空；示例为 `medium` | 可选推理强度 |
| `CODEX_TIMEOUT` | `300` | 单次 CLI 调用超时，单位秒 |
| `OPENAI_API_KEY` | 无 | API 后端密钥 |
| `OPENAI_BASE_URL` | 示例为 `https://api.openai.com/v1` | API 地址 |
| `OPENAI_MODEL` | 示例为 `your-model` | 必须替换为服务商可用模型 |
| `OPENALEX_API_KEY` | 无 | 可选检索服务密钥；额度取决于服务方政策 |
| `HOST` / `PORT` | `127.0.0.1` / `8000` | 后端监听地址与端口 |
| `CORS_ORIGINS` | localhost 与 127.0.0.1 的 5173 地址 | 逗号分隔的浏览器来源 |
| `PAPER_RESEARCH_DATA_DIR` | 源码根目录或安装包用户数据目录 | 运行数据根目录 |

## 数据管理

源码运行默认使用项目根目录；安装包运行默认使用用户目录下的 `.local/share/paper-research-agent`。设置 `PAPER_RESEARCH_DATA_DIR` 可将运行资料与代码分开，配置不会自动移动旧文件。改变数据根目录前，先停止后台任务并备份数据，再自行迁移需要的内容。

| 相对数据根目录的位置 | 内容 |
| --- | --- |
| `task_data/` | Web 任务、筛选结果、PDF、卡片、原文缓存、综述版本 |
| `history/`、`runs/` | 命令行历史或运行记录 |
| `backend/data/prompt_logs/` | 模型请求和响应记录，可能含完整研究内容 |
| `instruction_presets/`、`review_templates/` | 用户编辑的指令与范文 |
| `config/papers_keywords.json` | 个人论文与关键词配置 |
| `papers/` | 本地导入 PDF |

开发评估脚本的输出位置由各脚本参数决定，通常放在被 Git 忽略的 `outputs/`。备份时也要考虑这些自定义位置。

个人关键词配置缺失时会从空白初始化，公开模板为 `config/papers_keywords.example.json`。`manage_papers.py` 和 `extract_papers.py` 是辅助脚本，修改的是运行数据，不是共享样例。任务 JSON 采用 UTF-8 和原子替换写入。

`.env` 与 CLI 认证属于配置及凭据，不应打包进论文数据或公开备份。`PAPER_RESEARCH_DATA_DIR` 不会搬迁或替代 CLI 的认证目录。提示词日志、模板和文稿也可能包含未公开研究内容；发布前需要审查，不能只检查 API Key。

## CLI 与开发接口

```bash
paper-research --keywords "robot manipulation" "tactile sensing" --year-from 2024
python manage_papers.py list
```

CLI 的关键词研究路径与 Web 深度检索并非完全相同。需要自然语言多轮主题检索及完整综述工作台时，使用 Web 界面。

主要接口如下，参数以 `/docs` 的 schema 为准：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/tasks` | 创建关键词或深度检索任务 |
| `GET` | `/api/tasks/{task_id}` | 读取任务、结果与综述状态 |
| `POST` | `/api/tasks/{task_id}/write-review` | 创建综述版本，立即返回 review ID |
| `POST` | `/api/tasks/{task_id}/reviews/{review_id}/resume` | 继续可恢复的详细综述 |
| `POST` | `/api/tasks/{task_id}/reviews/{review_id}/cancel` | 停止并保存进度 |
| `GET` | `/api/tasks/{task_id}/reviews/{review_id}/export` | 导出已保存的 Markdown |

综述请求使用从 0 开始的 `paper_indices`；空数组表示主列表全部论文。默认 `mode="survey"`、`language="zh"`，同一个检索任务同时只运行一版综述。

## 常见问题

**搜索到零篇。** 先查看来源错误与实际查询；过多概念同时出现、缩写解释错误或过窄的年份范围都可能影响召回。不要直接推断该主题没有相关研究。

**论文已经找到，但没有进入主列表。** 检查补充阅读、待复核与排除分组。相关度与证据状态分开处理；原文不足时应补读，不应强行提高分数。

**无法读取 arXiv HTML。** 部分论文没有可用 HTML，或请求暂时失败。系统会检查已有 PDF 和原始摘要并标记降级；不会把摘要页当成全文。

**综述失败或中断。** 查看阶段和具体错误。可恢复版本使用“继续生成”；修改模型、材料或写作要求后应新建版本。原文引证或语义检查失败不应被简单当作网络重试处理。

**界面停在某个阶段。** 模型调用通常耗时较长，CLI 模式没有逐 token 输出。检查后端是否仍运行、模型调用是否超时，以及日志中的实际状态；刷新页面不会取消任务。

**页面显示 API 连接失败。** 开发模式需要同时运行前后端；Vite 默认把 `/api` 和 `/ws` 代理到 `localhost:8000`。改变后端端口时需要同步调整代理配置。

**能否直接部署到公网。** 当前没有账号认证或用户级授权，默认仅监听回环地址，并使用单进程任务状态。公开部署需要另行设计认证、授权、数据隔离、请求限额和反向代理；不能只修改监听地址。
