# 详细综述与证据评估协议

[项目首页](../README.md) · [架构说明](ARCHITECTURE.md)

本协议评估的是固定文献集合上的材料处理、写作与验证，不把文稿长度或引用数量当作事实准确率。公开仓库只提供方法与测试，个人综述、任务快照和模型调用日志由使用者本地保存。

## 固定输入与生成条件

先记录选定论文、主题、年份范围、写作要求、模型后端与配置。详细综述创建时保存输入快照；修改范围、模型或要求应新建版本，不直接篡改旧快照。

所选文献集合与检索全集不是同一概念。主列表、补充阅读和待复核的处理应明确说明，不能在生成后用全部检索结果的数量扩大综述覆盖声明。

## 五个独立的验证层次

| 层次 | 需要检查 | 能证明的范围 |
| --- | --- | --- |
| 资料获取 | 是否为真实全文；HTML/PDF/摘要分别有多少；缓存能否复用 | 材料来源与可访问程度 |
| 引用身份 | 全局 ID 是否对应同一论文；摘录是否来自所标段落 | 来源与摘录可追溯 |
| 正文覆盖 | 每篇是否分配到章节，并实际出现在正文或比较表 | 本次选定集合的引用覆盖 |
| 语义审校 | 引文是否支持论断，指标与条件是否一致 | 被检查到的具体事实问题 |
| 阅读与恢复 | 中断、重启、导出与版本是否一致 | 应用行为与文稿持久性 |

前一层通过不意味着后一层自动通过。有效原文引证仍可能被误解；全文可访问不意味着每段都被模型阅读；正文引用一篇论文不意味着已充分讨论其所有贡献。

## 资料获取测试

建议用小型、可公开分发的合成 fixture 覆盖以下情形：

- arXiv HTML 包含正文、方法、实验、公式、表格、章节和锚点。
- HTML 返回摘要页、错误模板、非 HTML 类型、过大响应或超时。
- 同版本缓存复用与失败缓存，冷缓存时的请求限速和取消。
- 没有可用 HTML，但已有本地 PDF；PDF 无可提取文本。
- 仅有原始摘要，以及只有元数据但没有任何原文。

HTML 优先策略不自动下载缺失 PDF，也不会把旧模型卡片或中文模型摘要视作原文。PDF 测试应检查物理页码；HTML 测试应检查章节/锚点和原文哈希。原始正文、参考文献与页面导航应正确区分。

## 引用与覆盖测试

每章需要检查全局引用编号、论文身份、段落 ID、逐字摘录及章节内正文引用。引用列表、代码、数学内容和普通链接不应被错误计入正文覆盖。不得用补写参考文献列表掩盖正文遗漏。

序列化差异与事实差异应分开处理。受限的 LaTeX/JSON 转义修复必须匹配同一段落中的唯一连续原文，保留修复前文本与位置，修复后重新通过完整校验。数字变化、错篇引用、拼接引文和歧义匹配不能被“格式修复”接受。

可在项目虚拟环境中离线复核一版已保存的详细综述：

```bash
python - path/to/reviews/REVIEW_ID <<'PY'
import json
import sys
from pathlib import Path

from backend.survey_validation import audit_coverage, validate_section

root = Path(sys.argv[1])
read = lambda path: json.loads(path.read_text(encoding="utf-8"))
plan = read(root / "outline.json")
records = read(root / "evidence.json")
sections = []
for section in plan["sections"]:
    output = read(root / "sections" / f"{section['id']}.json")
    sources = read(root / "sources" / f"{section['id']}.json")
    issues = validate_section(output, set(section["reference_ids"]), sources)
    if issues:
        raise SystemExit(f"{section['id']}: {issues}")
    sections.append({**section, **output})
print(json.dumps(audit_coverage(sections, records), ensure_ascii=False, indent=2))
PY
```

替换为自己的综述目录。该检查不调用模型，也不替代语义校读；它只验证保存的引用证据与覆盖关系，不重新从发布方网站核验原文。

## 语义校读

按研究分支、资料层级、数值密度和论文复用频率选择抽查范围，并记录选择方法。至少关注：

1. **输入与输出**：方法究竟预测状态、生成动作、选择技能，还是为规划评分。
2. **训练与推理**：训练监督是否在部署时可用；未来观测、特权状态或人工目标不能被写成部署输入。
3. **实验口径**：指标、任务、样本量、预算、基线、仿真/真机和统计不确定性是否一致。
4. **模型范围**：共享架构、共享权重、逐对象训练与逐轨迹拟合是否被混淆。
5. **能力边界**：当前选段未提供的细节不能被描述为论文没有；摘要级资料不能支持未披露实验参数。
6. **作者与综述观点**：作者报告、综述推断和未来实验建议是否明确区分。
7. **跨章节一致性**：同一论文的设置、数据与限制是否被不同章节改写成互相冲突的版本。

明确事实错误和错引应修正后再校验。重复、段落组织或比较表范围等编辑建议可以单独记录，不应伪装成不存在，也不应与不可核验的事实错误混为一谈。

## 中断、恢复与导出

使用模拟后端验证首次请求、部分完成、超时、取消、服务重启与快照损坏。恢复应复用通过校验的章节，保留原始模型响应，并拒绝混入变化后的材料或配置。

在浏览器中检查刷新、离开页面、返回同一任务、版本切换和目录定位。未完成正文应标明状态；在版本完成后，比较 API 返回的正文、`state.json`、`review.md` 与导出文件的内容或 SHA-256，确认保存与展示使用同一终稿。

## 运行记录与公开说明

本地评估可记录以下字段：输入数与来源层级、主题章节数、正文字符数、实际引用覆盖、逐条原文引证数、失败与重试次数、模型调用数、总耗时、人工或独立模型抽查范围、未解决问题，以及最终文稿指纹。

正文长度应区分中文字符、全部字符、Markdown 标记和参考文献；不同定义不能直接比较。模型调用数和耗时也应区分正常写作、主动取消、恢复与调试暂停。

发布质量结论时应说明采用了哪些检查、哪些材料未验证、抽查是否独立。不得由“所有选定论文已引用”推导出检索完整，由“引文匹配”推导出科学结论正确，或由单次成功运行承诺固定耗时与成本。

默认回归测试见 `tests/test_survey_evidence.py`、`tests/test_survey_validation.py`、`tests/test_survey_writer.py`、`tests/test_review_service.py` 与前端状态测试。真实模型评估单独执行，不应成为依赖维护者登录或私人论文库的 CI 前提。
